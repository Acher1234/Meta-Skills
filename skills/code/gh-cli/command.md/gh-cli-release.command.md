# gh-cli-release — Commands

`gh` 2.103.0. Flags not listed: `gh <command> --help`. Rules: `gh-cli` SKILL.md.
All accept `-R OWNER/REPO`. `<tag>` omitted on read commands → latest release.

## Read and download

| Command | Description |
|---------|-------------|
| `gh release list [-L <n>] [--exclude-drafts] [--exclude-pre-releases] [-O asc\|desc] [--json <fields>]` | Releases of the repo |
| `gh release view [<tag>] [--json <fields>]` | One release: notes and assets |
| `gh release download [<tag>] [-p <glob>]… [-D <dir>] [--clobber\|--skip-existing]` | Download assets |
| `gh release download <tag> -p <asset> -O <file>` | One asset to a given file (`-O -` = stdout) |
| `gh release download <tag> -A zip\|tar.gz` | Source archive |

`release view` fields: `tagName`, `name`, `body`, `isDraft`, `isPrerelease`,
`isImmutable`, `publishedAt`, `targetCommitish`, `url`, `assets`.

## Create and edit — confirm first

A published release notifies watchers: prefer `-d` (draft) when unsure.

| Command | Description |
|---------|-------------|
| `gh release create <tag> [<files>…] -t "<title>" -F <notes-file> [-d] [-p] [--target <branch\|sha>] [--latest[=false]]` | New release with assets (`-d` draft, `-p` prerelease) |
| `gh release create <tag> --generate-notes [--notes-start-tag <tag>]` | Notes generated by GitHub from merged PRs |
| `gh release create <tag> --notes-from-tag` | Notes from the annotated tag message |
| `gh release create <tag> --verify-tag …` | Abort if the tag does not exist on the remote (otherwise it is created from `--target`) |
| `gh release create <tag> --fail-on-no-commits …` | Abort if nothing changed since the last release |
| `gh release edit <tag> [-t "<title>"] [-F <notes-file>] [--draft=false] [--prerelease[=false]] [--latest] [--tag <new-tag>] [--target <ref>]` | Edit; `--draft=false` publishes a draft |
| `gh release upload <tag> <files>… [--clobber]` | Add assets (`--clobber` replaces same-name assets) |
| `gh release delete-asset <tag> <asset-name> -y` | Remove one asset |
| `gh release delete <tag> -y [--cleanup-tag]` | Delete the release (`--cleanup-tag` also deletes the git tag) |

Without `<tag>` or notes flags `gh` prompts: always pass the tag and one of
`-F`, `-n`, `--generate-notes`, `--notes-from-tag`. Asset label:
`'<file>#<display label>'`. `--discussion-category <name>` opens a discussion
for the release.

## Verify (attestations)

| Command | Description |
|---------|-------------|
| `gh release verify [<tag>] [--format json]` | Verify the release attestation (immutable releases) |
| `gh release verify-asset [<tag>] <file-path> [--format json]` | Verify that a local file is an asset of that release |
| `gh attestation verify <file-path\|oci://<image>> -R <repo>\|-o <owner> [--format json]` | Verify build provenance of an artifact |
| `gh attestation verify <file> -R <repo> --signer-workflow <owner>/<repo>/.github/workflows/<file> [--source-ref <ref>] [--deny-self-hosted-runners]` | Same, pinned to the workflow / ref that built it |
| `gh attestation verify <file> -o <owner> --predicate-type <uri>` | Another predicate (default: SLSA provenance v1) |
| `gh attestation download <file-path\|oci://<image>> -R <repo>\|-o <owner> [-L <n>]` | Save the attestation bundle for offline use |
| `gh attestation verify <file> -R <repo> -b <bundle.jsonl> [--custom-trusted-root <file>]` | Offline verification from a bundle |
| `gh attestation trusted-root [--verify-only]` | Print `trusted_root.jsonl` for offline verification |

Exit code 0 = verified. Alias: `gh at`.
